# Gemini Live API 側でサポートされている対話・データ制御機能調査レポート

クライアント側（iOSアプリ）で複雑な音声解析やミュート制御を実装する代わりに、**Gemini Live API（WebSocket）側がネイティブで提供している機能**で吸収できるポイントについて調査しました。

---

## 1. Live API がネイティブで提供するデータ・対話制御機能

Gemini Live API（双方向 WebSocket）には、データコントロールやターン管理を行うための以下の設定パラメータおよびシグナルが組み込まれています。

### ① サーバー側での音声活動検知 (Server-side VAD)
*   **機能**: API側で高性能な VAD が常時稼働しており、ユーザーが話し始めたタイミングと話し終えたタイミングを自動で検知します。
*   **吸収できる点**: クライアント側（iOS）で音声データをデシベル解析したり、ローカルVAD（発話区間検出）プログラムを実装したりする必要がありません。クライアントは単にマイク音声をそのままストリームするだけで済みます。

### ② 割り込み（Barge-in）のネイティブ検知と制御
*   **機能**: アシスタントが応答を喋っている最中にユーザーが話し始めると、サーバー側が割り込み（Barge-in）を検知し、応答生成を即座に破棄（キャンセル）します。
*   **クライアントへのシグナル**: 割り込みが発生すると、サーバーはWebSocket経由で即座に `interrupted` イベント（iOSアプリで受信する `type: "interrupt"`）を送信します。
*   **クライアント側の責務**: クライアントは `interrupt` を受信した瞬間に**「ローカルの音声再生バッファ（キュー）をクリアする」だけで、物理的な割り込みによる音声の停止を実装**できます（現行のSwiftクライアントには既にこのクリア処理が入っています）。

### ③ 割り込み動作のカスタマイズ設定 (`activity_handling`)
*   **機能**: 双方向対話において、ユーザーの発話が応答を遮る（割り込む）かどうかをAPIの設定で変更できます。
*   **設定値 (`realtimeInput.activity_handling`)**:
    1.  `START_OF_ACTIVITY_INTERRUPTS` (デフォルト): ユーザーが喋り始めると即座に応答を中断する。
    2.  **`NO_INTERRUPTION`**: ユーザーが喋りかけても、Geminiは応答の生成と送信を**中断せず最後まで話し続ける**。
*   **吸収できる点**: 周囲のノイズやマイクへのエコーバックによってGeminiが頻繁に途切れてしまう（誤割り込み）現象を防ぎたい場合、バックエンド側の設定を `NO_INTERRUPTION` に変更するだけで、クライアント側のコードを書き換えることなく「割り込み無効」の安定した対話を実現できます。

### ④ 完全マニュアルターン制御（自動VADの無効化）
*   **機能**: `realtime_input_config.automatic_activity_detection` を `disabled: true` にすることで、サーバー側での自動発話検知を完全にオフにできます。
*   **対話方法**: この状態では、クライアントから明示的に `ActivityStart` と `ActivityEnd` という制御イベントをWebSocket経由で送信することで、Geminiに「ここから聞き取り」「ここまでで発話終了」を指示します。
*   **吸収できる点**: スマートグラスの物理ボタンを押している間だけ録音・送信する「プッシュ・トゥ・トーク（PTT）」形式を採用する場合、この機能を使うことで、周囲の環境音に関わらず完璧なターン管理が可能です。

## 2. 実装へのアプローチ提案

上記調査結果に基づき、本プロジェクトでの最適なデータ制御のアプローチは以下のように整理されます。

### アプローチ 1: iOS標準のノイズキャンセル ＋ API標準機能（最もシンプル・推奨）
*   **実装**:
    *   iOSの `AVAudioSession` カテゴリを `mode: .voiceChat` に設定（実装済）。これにより、iOS本体のハードウェアによる **Acoustic Echo Cancellation (AEC)** が働き、スマートグラスのスピーカー音の回り込みを自動カットします。
    *   ターン制御はGemini Live APIのサーバー側VADと `interrupt` シグナルに100%委ねます。
*   **メリット**: 追加のコード実装が不要で、標準のフルデュプレックス対話が成立します。

### アプローチ 2: バックエンド側での割り込み無効化設定 (`NO_INTERRUPTION`)
*   **実装**:
    *   FastAPIバックエンド（中継サーバー）がVertex AIにセッションを張る際の初期設定（`LiveConnectConfig`）で、`activity_handling: "NO_INTERRUPTION"` を指定する。
*   **メリット**: グラスの音量や周囲の雑音による予期せぬ応答の停止（誤割り込み）が完全に解消され、Geminiが必ず最後まで話し終えるようになります。

### アプローチ 3: クライアント側でのマイクパケット抑止（完全にエコーを防ぐ場合）
*   **実装**:
    *   iOS側で、スピーカー再生中（Geminiが喋っている間）は `sendAudioChunk` を行わない（マイク入力を捨てる）制御を追加する。
*   **メリット**: 通信帯域の節約になり、サーバー側へのエコーバックを完全に物理遮断できます。
